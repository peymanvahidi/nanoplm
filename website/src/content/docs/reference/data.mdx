`data.yaml` describes one FASTA-to-shards pipeline. Scaffold it with `nanoplm data get-yaml`, edit it, then run `nanoplm data from-yaml` to produce the binary shards and the `.data_manifest`. See [Prepare data](/nanoplm/pipeline/data/) for the walkthrough and the [CLI reference](/nanoplm/reference/cli/) for the commands.

Everything the pipeline writes goes under `output_dir`, which is the folder `pretrain.yaml`'s `dataset_dir` points at. Each entry under `sources` (only one is supported for now) names a `fasta` to build from or a `prepared` folder another `data.yaml` built, and may set any `data_params` field to override it for that source. `data_params` holds the defaults for every source. A `cluster_subsampling` block under a source switches it to training on one random member of every cluster per epoch, see [Cluster subsampling](/nanoplm/guides/cluster-subsampling/).

Two fields reach beyond this file. [`max_seq_len`](#data-data_params-max_seq_len) is recorded in the manifest and is the value pretraining reads back for its token math, which is why you never set a sequence length in `pretrain.yaml`. [`register_tokens`](#data-data_params-register_tokens) is recorded the same way and injected into the model config at pretrain time.

The fields below are generated from the `get-yaml` template itself, so they cannot drift from the tool.

## sources
Each key under `sources` is a name you pick (letters, digits and `_`); the template's is `swissprot`. Its value is the spec below. Set exactly one of `fasta` and `prepared`. Any [`data_params`](#data_params) field set on a source overrides the default for that source, for example `max_seq_len: 1024`. Relative paths resolve against the **directory the YAML sits in**, not the directory you run the command from.
