`data.yaml` says which FASTA to read and how to turn it into binary shards. Scaffold it with `nanoplm data get-yaml`, edit it, then run `nanoplm data from-yaml`. [Prepare data](/nanoplm/pipeline/data/) walks through a run, and the [CLI reference](/nanoplm/reference/cli/#data) lists the commands.

The file has three parts: `output_dir`, the folder everything is written to and `pretrain.yaml`'s `dataset_dir` points at; `sources`, the FASTA to build from (one source for now); and `data_params`, the settings every source uses unless it sets its own. [`max_seq_len`](#data-data_params-max_seq_len) and [`register_tokens`](#data-data_params-register_tokens) are recorded in the manifest and read back by pretraining, so `pretrain.yaml` has neither key.

The fields below are generated from the `get-yaml` template, so they match the tool.

## sources
Each key under `sources` is a name you pick (letters, digits and `_`); the template's is `swissprot`. It also names the folder under `output_dir` for that source's intermediate files. Set exactly one of `fasta` and `prepared`. Any [`data_params`](#data_params) field set on a source overrides the default for that source, for example `max_seq_len: 1024`. Relative paths resolve against the **folder `data.yaml` is in**, not the folder you run the command from.

### cluster_subsampling
The template ships this block commented out. Writing it under a source turns cluster subsampling on; there is no `enabled` switch. See [Cluster subsampling](/nanoplm/guides/cluster-subsampling/).
