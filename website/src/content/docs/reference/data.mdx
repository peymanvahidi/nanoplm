`data.yaml` describes one FASTA-to-shards pipeline. Scaffold it with `nanoplm data get-yaml`, edit it, then run `nanoplm data from-yaml` to produce the binary shards and the `.data_manifest`. See [Prepare data](/nanoplm/pipeline/data/) for the walkthrough and the [CLI reference](/nanoplm/reference/cli/) for the commands.

The file has two blocks. `data_dirs` names the file each pipeline stage reads and writes; `data_params` sets the knobs those stages use. Paths resolve relative to the directory you **run the command from**, not the directory the YAML sits in.

Two fields reach beyond this file. [`max_seq_len`](#data-data_params-max_seq_len) is recorded in the manifest and is the value pretraining reads back for its token math, which is why you never set a sequence length in `pretrain.yaml`. [`register_tokens`](#data-data_params-register_tokens) is recorded the same way and injected into the model config at pretrain time.
