`data.yaml` says which FASTA files to read and how to turn them into binary shards. Scaffold it with `nanoplm data get-yaml`, edit it, then run `nanoplm data from-yaml`. [Prepare data](/nanoplm/pipeline/data/) walks through a run, and the [CLI reference](/nanoplm/reference/cli/#data) lists the commands.

The file has three parts:

- `output_dir`, the folder every file is written to. `pretrain.yaml`'s `dataset_dir` points here.
- `sources`, the FASTAs to build from. Two or more make a mix, drawn by [`weight`](#data-sources-weight); see [Mixing datasets](/nanoplm/guides/mixing/).
- `data_params`, the settings every source uses unless it sets its own.

[`max_seq_len`](#data-data_params-max_seq_len) and [`register_tokens`](#data-data_params-register_tokens) also go into the manifest, and pretraining reads them from there, so `pretrain.yaml` has neither key.

The fields below are generated from the `get-yaml` template, so they match the tool. Relative paths resolve against the folder `data.yaml` is in, not the folder you run the command from.

## sources
Each key under `sources` is a name you pick, using letters, digits and `_`. The template's is `swissprot`. It also names the folder under `output_dir` that holds this source's intermediate files. Set exactly one of `fasta` and `prepared`. A [`data_params`](#data_params) field set on a source, such as `max_seq_len: 1024`, overrides the default for that source. `val_ratio` and `val_size` are the exception: they are set once, in `data_params`, for all sources.

### cluster_subsampling
The template has this block commented out. Writing it under a source turns cluster subsampling on. There is no `enabled` key. See [Cluster subsampling](/nanoplm/guides/cluster-subsampling/).
