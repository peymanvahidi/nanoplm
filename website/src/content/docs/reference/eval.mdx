`eval.yaml` scores a trained checkpoint on downstream benchmarks. Scaffold it with `nanoplm eval get-yaml`, edit it, then run `nanoplm eval from-yaml`. See [Evaluate](/nanoplm/pipeline/eval/) for the walkthrough.

The surface is flat (a single `eval:` block) and it is short because a checkpoint is self-describing. It carries its own `model_config.yaml`, so the one field you must supply is [`checkpoint_dir`](#eval-checkpoint_dir), which accepts either a `checkpoint-*` directory or a `run-*` directory (in which case the newest checkpoint inside it is used). Required fields carry a teal asterisk.

One constraint is worth knowing before you run it: evaluation loads **pure-torch checkpoints only**.
