import { Steps, FileTree } from '@astrojs/starlight/components';

You are going to pretrain a real protein language model (a 2.3M-parameter ModernBERT-style
encoder) on 20,000 SwissProt sequences, then score it on a downstream benchmark. Every command is
run from the same working directory, and each stage hands its artifacts to the next.

**What you need**

- A supported install: Linux + Hopper GPU + CUDA 13, via `nanoplm deps install`. See
  [Install](/nanoplm/start/install/).
- The `eval` extra for Stage 3 (`uv pip install -e ".[eval]"` or the GitHub equivalent).
- About 30 minutes: roughly 10 for the SwissProt download and tokenization, a few for training, and
  the rest for benchmarking.

:::note
`use_packing` defaults to `true` and uses FlashAttention-3, which `nanoplm deps install` already
puts in the env.
:::

## Stage 1: Build the dataset

<Steps>

1. **Scaffold the config.** This writes `data.yaml`, which you edit, and `dvc.yaml`, which nanoPLM
   generates and you never edit.

   ```bash
   nanoplm data get-yaml
   # Wrote data.yaml and dvc.yaml in <cwd>.
   # Edit data.yaml and run `nanoplm data from-yaml` to execute.
   ```

2. **Check three keys.** The template already points at SwissProt, so you can run it as it is.
   These three keys decide which sequences you train on, how many, and how long they can be.

   ```yaml title="data.yaml" {4,8,10}
   output_dir: "output/data/pretrain_data"   # pretrain.yaml reads from here
   sources:
     swissprot:
       fasta: swissprot     # or uniref50, uniref90, a URL, or a local FASTA
   # ...

   data_params:
     max_seqs: 20000        # -1 = all; 20k trains fast and still learns
     min_seq_len: 20
     max_seq_len: 512       # longer sequences are dropped
     # ...
   ```

3. **Run the pipeline.** This downloads SwissProt, checks and filters the sequences, splits them
   into train and validation sets, and tokenizes them.

   ```bash
   nanoplm data from-yaml
   # data.yaml: 1 source -> <cwd>/output/data/pretrain_data
   # source     fasta                         max seqs  len     val  clustering
   # swissprot  uniprot_sprot.fasta.gz (url)  20,000    20-512  0.1  off
   # Regenerated <cwd>/dvc.yaml
   # Initialized DVC repository in: <cwd> (cache.type hardlink,symlink)
   # Rebuild: all (first run)
   # Running dvc repro (full pipeline)...
   # ...
   # Pretraining data pipeline complete.
   #
   #   Source:          https://ftp.uniprot.org/pub/databases/uniprot/knowledgebase/complete/uniprot_sprot.fasta.gz
   #   Total sequences: 20000
   #     Train:         18000
   #     Val:           2000
   #   Manifest:        <cwd>/output/data/pretrain_data/.data_manifest
   #   Set pretrain.yaml's dataset_dir to <cwd>/output/data/pretrain_data.
   ```

   `from-yaml` prints the table at the top before anything runs, so you can check the file and
   settings first ([columns explained here](/nanoplm/pipeline/data/#read-the-table-before-the-run)).
   If the `check` stage stops on invalid sequences, run `nanoplm data from-yaml --fix`
   ([details](/nanoplm/pipeline/data/#invalid-sequences-will-stop-you-once)).

</Steps>

You now have the tokenized sequences in binary shard files, and a manifest that describes them:

<FileTree>

- output/data/pretrain_data/
  - train/
    - shard_0000.bin
    - shard_0000.idx.npy
    - ...
  - val/
    - shard_0000.bin
    - shard_0000.idx.npy
  - .data_manifest **pretraining reads max_seq_len and the shard folders from here**

</FileTree>

## Stage 2: Pretrain

<Steps>

1. **Scaffold the config.**

   ```bash
   nanoplm pretrain get-yaml
   # Template written to: <cwd>/pretrain.yaml
   ```

   The file is long (+200 lines) because it exposes every knob nanoPLM's pretraining has. You need to touch
   six of them. Leave the rest alone; the defaults are good. The
   [pretrain.yaml reference](/nanoplm/reference/pretrain/) documents the others when you want them.

2. **Shrink the model.** The template ships a 1024-wide, 16-layer model. Replace the top of the
   `model:` block with something that trains in minutes:

   ```yaml title="pretrain.yaml"
   model:
     hidden_size: 256
     intermediate_size: 512
     num_hidden_layers: 4
     num_attention_heads: 4
     vocab_size: 32          # the protein tokenizer's vocabulary: leave it
     # ... leave the rest of the model block as generated
   ```

3. **Set the batch and the budget.** These four keys under `pretraining:` are the ones that decide
   what a run costs.

   :::note
   This is in the same `pretrain.yaml` file, but in `pretraining` block. 
   :::

   ```yaml title="pretrain.yaml"
   # ...
   pretraining:
     dataset_dir: "output/data/pretrain_data"  # where Stage 1 wrote its shards

     micro_batch_seqs: 16          # sequences per GPU per forward pass: your VRAM knob
     global_batch_tokens: 65536    # tokens per optimizer step: 16 seqs x 512 tokens x 8 accum

     warmup_steps: 20              # optimizer steps, not a ratio
     stable_tokens: 8000000        # tokens up to the pre-decay checkpoint (warmup is inside this)
     decay_tokens: 2000000         # additional anneal tokens on top
   # ...
   ```

   There are **no epochs** in nanoPLM. Duration is a token budget, and the dataset is replayed as
   many times as the budget needs. The default `lr_schedule` is `wsd`, so your run is
   `stable_tokens` + `decay_tokens` = 10M tokens total: warm up, hold the peak learning rate, then
   anneal. Gradient accumulation is *inferred* from these numbers: never set it.

4. **Train.**

   ```bash
   nanoplm pretrain from-yaml
   # Using pure-torch model and training loop
   # Total Trainable Parameters: 2306848
   # Flash attention available: True
   # ...
   # [total] Budget: 10,092,544 tokens → ≈1.6 passes over the train set (each sample seen ~1.6×)
   # [step 1/154] loss=3.4412 lr=5.00e-06 grad_norm=1.8834 tok/s=412,190 real_tok/step=65,536 dt=159.00ms
   # ...
   # [step 123/154] loss=2.5107 lr=1.00e-04 grad_norm=0.4630 tok/s=438,024 real_tok/step=65,536 dt=149.60ms
   # ...
   # [step 154/154] loss=2.3915 lr=1.09e-05 grad_norm=0.3901 tok/s=437,551 real_tok/step=65,536 dt=149.80ms
   ```

   Your 10M-token budget resolved to 154 optimizer steps: 123 stable, then 31 of decay. Watch `lr`
   hold flat and then fall away after step 123: that is the WSD schedule doing its job.

</Steps>

:::note
The scaffolded `pretrain.yaml` already sets `pure_torch: true`, so no `--pure-torch` flag is needed.
Pure-torch is the only pretraining backend, and its checkpoints are what `nanoplm eval` loads.
:::

The run directory is named `<run_name>-<DDMMHHMM>`, so yours will differ:

<FileTree>

- output/pretraining_checkpoints/
  - run-14071932/
    - run_name.txt
    - checkpoint-stable-end/ saved automatically at the stable→decay boundary
    - checkpoint-final/ **your trained model**
      - pytorch_model.bin
      - model_config.yaml **the architecture, so eval needs nothing but a path**
      - pretrain_config.yaml
      - training_state.json
      - ...

</FileTree>

## Stage 3: Evaluate

<Steps>

1. **Scaffold the config.**

   ```bash
   nanoplm eval get-yaml
   # Template written to: <cwd>/eval.yaml
   ```

2. **Point it at your checkpoint.** This is the only value eval cannot infer: everything else about
   the model comes out of `model_config.yaml` inside the checkpoint.

   ```yaml title="eval.yaml"
   eval:
     checkpoint_dir: "output/pretraining_checkpoints/run-14071932/checkpoint-final"
     framework: [pgym]   # ProteinGym, zero-shot: the model scores mutants directly
     output_dir: "autoeval_output"
     development_mode: true
     # ...
   ```

3. **Run the benchmark.** nanoPLM scores the benchmark's mutants with your model's MLM head. No
   probe is trained on top.

   ```bash
   nanoplm eval from-yaml
   # Adding PGYM zero-shot: method=masked_marginals, batch_size=60
   # Starting autoeval: frameworks=['pgym'], development_mode=True
   # ============================================================
   # ...
   # ============================================================
   # AUTOEVAL COMPLETE in 812.4s — Final Report Summary
   # Frameworks in report: ['PGYM']
   # ============================================================
   ```

</Steps>

The combined report lands at the top of `output_dir`, with per-framework artefacts under the
embedder's directory, which defaults to the checkpoint's directory name:

<FileTree>

- autoeval_output/
  - autoeval_report_checkpoint-final.json
  - checkpoint-final/
    - PGYM/ per-task results
    - ...

</FileTree>

## Verify

You are done when all four are true:

- `output/data/pretrain_data/.data_manifest` exists and reports 18,000 train and 2,000 val sequences.
- Training reached `[step 154/154]` and your loss fell from around 3.4 to under 2.5. A tiny model on
  10M tokens will not be state of the art; a falling loss is what proves the pipeline works.
- `output/pretraining_checkpoints/<your-run>/checkpoint-final/pytorch_model.bin` exists. **That file
  is your protein language model**, and `model_config.yaml` beside it describes its architecture.
- `autoeval_output/autoeval_report_checkpoint-final.json` holds a benchmark report.
