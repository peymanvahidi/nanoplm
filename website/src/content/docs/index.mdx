**nanoPLM turns a FASTA file into a trained, benchmarked protein language model.** The whole
pipeline is three YAML files and three commands — no training script to write, no research
codebase to fork.

## The mental model

Pretraining a PLM is three stages: turn sequences into tokens, train a masked-language model on
those tokens, then score the result on downstream benchmarks. nanoPLM gives each stage one config
file and one command, and defines the artifacts that pass between them. Those artifacts are the
whole design: the data stage writes a `.data_manifest` that the pretraining stage reads its
sequence length back out of, and the pretraining stage writes checkpoints that carry their own
`model_config.yaml`, so evaluation needs nothing but a path.

<PipelineDiagram />

Because each stage is self-describing, you never repeat yourself. `max_seq_len` is set once, in
`data.yaml`. The model architecture is written into the checkpoint, so `eval.yaml` never restates
it.

## The loop

Every stage has the same two verbs. `get-yaml` scaffolds a fully-commented config, you edit it, and
`from-yaml` runs it.

```bash
nanoplm pretrain get-yaml
# Template written to: /work/pretrain.yaml

$EDITOR pretrain.yaml

nanoplm pretrain from-yaml --pure-torch
# Using pure-torch model and training loop
# Total Trainable Parameters: 2306848
# Flash attention available: True
# [step 1/154] loss=3.4412 lr=5.00e-06 grad_norm=1.8834 tok/s=412,190 ...
# ...
```

Swap `pretrain` for `data` or `eval` and the shape is identical.

## Quickstart

```bash
pip install nanoplm

nanoplm data get-yaml && nanoplm data from-yaml
nanoplm pretrain get-yaml && nanoplm pretrain from-yaml --pure-torch
nanoplm eval get-yaml && nanoplm eval from-yaml
```

The defaults are wired to chain: `data.yaml` writes shards to `output/data/pretrain_data/`, which
is exactly where `pretrain.yaml` looks for them. The one value the defaults cannot guess is
`eval.checkpoint_dir` — open `eval.yaml` and point it at the run you trained above.

Success looks like this:

```bash
nanoplm data from-yaml
# Running dvc repro (full pipeline)...
# ...
# Pretraining data pipeline complete.
#
#   Source:          https://ftp.uniprot.org/pub/databases/uniprot/knowledgebase/complete/uniprot_sprot.fasta.gz
#   Total sequences: 20000
#     Train:         18000
#     Val:           2000
#   Manifest:        /work/output/data/pretrain_data/.data_manifest
```

:::note
`--pure-torch` is not optional. Pretraining requires you to pick a backend — `--pure-torch` or
`--pure-te` — and pure-torch is the one to use. See [Choose a backend](/nanoplm/guides/backends/).
:::
