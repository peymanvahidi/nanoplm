**nanoPLM turns a FASTA file into a trained, benchmarked protein language model easier than ever.** The whole
pipeline is three YAML files and six commands, this helps you to focus on your research question instead of spending a long time for engnieering.

## The mental model

Pretraining a PLM is three stages: turn sequences into tokens, train a masked-language model on
those tokens, then score the result on downstream benchmarks. nanoPLM gives each stage one config
file and two commands, and defines the artifacts to make your life easier. Because each stage
describes itself on disk, you never repeat yourself. The data stage writes a
[`.data_manifest`](/nanoplm/pipeline/#data-writes-shards-plus-a-manifest) recording what it decided so pretraining
reads those back instead of asking you to retype them. The pretraining stage then writes checkpoints carrying their own
[`model_config.yaml`](/nanoplm/pipeline/#pretrain-writes-a-self-describing-checkpoint), so evaluation needs nothing but a path.

## The loop

Every stage has the same two verbs. `get-yaml` scaffolds a fully-commented config, you edit it, and
`from-yaml` runs it. Shown for pretraining; swap `pretrain` for `data` or `eval` and the shape is
identical.

<Steps>

1. **Scaffold** a fully-commented config.

   ```bash frame="terminal"
   nanoplm pretrain get-yaml
   # writes pretrain.yaml
   ```

2. **Edit** it.

   ```bash frame="terminal"
   $EDITOR pretrain.yaml
   ```

3. **Run** it.

   ```bash frame="terminal"
   nanoplm pretrain from-yaml
   # Using pure-torch model and training loop
   # Total Trainable Parameters: 2306848
   # Flash attention available: True
   # [step 1/154] loss=3.4412 lr=5.00e-06 grad_norm=1.8834 tok/s=412,190 ...
   # ...
   ```

</Steps>

## Quickstart

```bash
uv venv && source .venv/bin/activate
uv pip install "nanoplm @ git+https://github.com/peymanvahidi/nanoplm" \
    --extra-index-url https://download.pytorch.org/whl/cu130
nanoplm deps install

nanoplm data get-yaml && nanoplm data from-yaml
nanoplm pretrain get-yaml && nanoplm pretrain from-yaml
# optional: uv pip install -e ".[eval]"   (or the GitHub form)
nanoplm eval get-yaml && nanoplm eval from-yaml
```

Full install details (clusters, verify, the `eval` extra): [Install](/nanoplm/start/install/).

The defaults are wired to chain: `data.yaml` writes shards to `output/data/pretrain_data/`, which
is exactly where `pretrain.yaml` looks for them. The one value the defaults cannot guess is
`eval.checkpoint_dir`: open `eval.yaml` and point it at the run you trained above.

:::note
The stock `pretrain.yaml` sets `pure_torch: true`, so `from-yaml` needs no backend flag. To use
Transformer Engine instead, set `pure_te: true` and turn off pure-torch in the YAML. See
[Choose a backend](/nanoplm/guides/backends/).
:::

For the real thing (a tiny model trained and evaluated end to end, with the edits spelled out),
follow [Your first PLM](/nanoplm/start/first-plm/).
