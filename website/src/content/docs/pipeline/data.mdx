import { FileTree, Steps } from '@astrojs/starlight/components';

The data stage takes a FASTA file (a UniProt download, a URL or a local file) and writes the two things pretraining reads: **tokenized binary shards** and a **`.data_manifest`**. In between it runs these stages:

```
download → extract → check → shuffle → filter → split → tokenize → write manifest
```

## Run it

<Steps>

1. Scaffold the config.

   ```sh
   nanoplm data get-yaml
   ```

   ```text title="Output"
   Wrote data.yaml and dvc.yaml in <cwd>.
   Edit data.yaml and run `nanoplm data from-yaml` to execute.
   ```

2. Edit `data.yaml` (the whole file is shown [below](#the-whole-config)). The template already builds 20,000 SwissProt sequences, so you can run it as it is.

3. Run the pipeline.

   ```sh
   nanoplm data from-yaml
   ```

   ```text title="Output (trimmed)"
   data.yaml: 1 source -> <cwd>/output/data/pretrain_data
   source     fasta                         max seqs  len     val  clustering
   swissprot  uniprot_sprot.fasta.gz (url)  20,000    20-512  0.1  off
   Regenerated <cwd>/dvc.yaml
   Initialized DVC repository in: <cwd> (cache.type hardlink,symlink)
   Rebuild: all (first run)
   Running dvc repro (full pipeline)...
   # ...
   Wrote manifest: output/data/pretrain_data/.data_manifest

   Pretraining data pipeline complete.

     Source:          https://ftp.uniprot.org/pub/databases/uniprot/knowledgebase/complete/uniprot_sprot.fasta.gz
     Total sequences: 20000
       Train:         18000
       Val:           2000
     Manifest:        <cwd>/output/data/pretrain_data/.data_manifest
     Set pretrain.yaml's dataset_dir to <cwd>/output/data/pretrain_data.
   ```

</Steps>

The stages run through [DVC](https://dvc.org/): `from-yaml` regenerates `dvc.yaml` from your config and runs `dvc repro`. You never edit `dvc.yaml`. DVC records what each finished stage produced, so a second run, or a run after an interrupted one, skips every stage whose inputs have not changed. A download cut off halfway starts again from the beginning.

## Use your own FASTA

Point `fasta` at the file. A relative path is relative to the folder `data.yaml` is in. The file is read where it is, never copied. The source name (`mine` here) is yours to pick. It names the folder for this source's intermediate files.

```yaml title="data.yaml"
sources:
  mine:
    fasta: my_proteins.fasta   # or .fasta.gz
```

```text title="Output (first lines)"
data.yaml: 1 source -> /work/output/data/pretrain_data
source  fasta                               max seqs  len     val  clustering
mine    my_proteins.fasta (local, 66.0 kB)  200       20-512  0.1  off
```

`fasta` accepts three kinds of value:

- a shortcut for a UniProt file, from the table below;
- a URL (`http://`, `https://` or `ftp://`), downloaded once into `output_dir/downloads/`;
- a local `.fasta` or `.fasta.gz` file.

| Shortcut | URL |
| --- | --- |
| `swissprot` | `https://ftp.uniprot.org/pub/databases/uniprot/knowledgebase/complete/uniprot_sprot.fasta.gz` |
| `trembl` | `https://ftp.uniprot.org/pub/databases/uniprot/knowledgebase/complete/uniprot_trembl.fasta.gz` |
| `uniref50` | `https://ftp.uniprot.org/pub/databases/uniprot/uniref/uniref50/uniref50.fasta.gz` |
| `uniref90` | `https://ftp.uniprot.org/pub/databases/uniprot/uniref/uniref90/uniref90.fasta.gz` |
| `uniref100` | `https://ftp.uniprot.org/pub/databases/uniprot/uniref/uniref100/uniref100.fasta.gz` |

Start with SwissProt (about 570k sequences). It downloads in minutes, which is enough to check the whole pipeline before a UniRef-scale run.

Instead of `fasta`, a source can name `prepared:`, a folder another `data.yaml` already built. `from-yaml` checks its manifest, prints what it holds and builds nothing. With only a `prepared` source, `output_dir` can be left out.

To train on one random member of every cluster per epoch (for example UniRef90 sequences under UniRef50 clusters), add a `cluster_subsampling` block to the source. See [Cluster subsampling](/nanoplm/guides/cluster-subsampling/).

## The whole config

This is the template with its commented examples left out.

```yaml title="data.yaml"
output_dir: "output/data/pretrain_data"   # every file goes here; pretrain.yaml's dataset_dir points here

# One entry per FASTA (one source for now).
# weight = share of training sequences (not tokens); weights must sum to 1.
sources:
  swissprot:
    fasta: swissprot     # swissprot, trembl, uniref50, uniref90, uniref100, a URL, or a local .fasta/.fasta.gz
    weight: 1.0
    # max_seq_len: 1024  # any data_params field set here overrides it for this source

  # (a commented UniRef50 cluster-subsampling example and a `prepared:` example follow)

data_params:
  max_seqs: 20000        # -1 = all
  min_seq_len: 20        # shorter sequences are dropped
  max_seq_len: 512       # longer sequences are dropped
  val_ratio: 0.1         # share held out for validation loss
  drop_invalid_sequences: false  # true: drop sequences with unknown residues instead of stopping

  # Rarely changed
  shuffle: true          # shuffle before the train / val split
  shuffle_seed: 24
  samples_per_shard: 2000  # raised automatically when a cluster pool needs it
  max_workers: 2         # tokenizer processes and MMseqs2 threads; -1 = all cores
  register_tokens: 0     # 0, 1 or 2 scratch tokens after EOS
```

With one source, `weight` must be `1.0` or left out.

`max_seqs`, `min_seq_len`, `max_seq_len` and `val_ratio` are required. The other `data_params` can be left out. The template's values are the defaults, and writing a default out or deleting it reruns nothing. Each key is described in the [data.yaml reference](/nanoplm/reference/data/).

:::caution[max_seq_len is set here and nowhere else]
`max_seq_len` is written into `.data_manifest`, and pretraining reads it back to compute gradient accumulation, `grad_accum = ceil(global_batch_tokens / (micro_batch_seqs × max_seq_len × world_size))`. There is no `max_seq_len` key in `pretrain.yaml`. To train on longer sequences, change it here and run the data stage again, because the shards themselves change.
:::

Attention cost grows with the square of the sequence length, so `512` is a cheap place to start. Raise it when your proteins need the context.

## Read the table before the run

Before any stage runs, `from-yaml` prints one row per source and one line saying what will run. A wrong `fasta`, a `max_seqs` you forgot, or a full rebuild you did not expect shows up here, before hours of work.

```text
data.yaml: 1 source -> /work/output/data/pretrain_data
source  fasta                               max seqs  len     val  clustering
mine    my_proteins.fasta (local, 66.0 kB)  200       20-512  0.1  off
Regenerated /work/dvc.yaml
Rebuild: all (first run)
```

| Column | Shows |
| --- | --- |
| `fasta` | The file the stages read. `(url)`: it will be downloaded. `(reuse, 40.2 kB, 2026-09-01)`: a file with that name, written on that date, is already in `output_dir/downloads/`. `(local, 66.0 kB)`: a local file, read where it is. |
| `max seqs` | `max_seqs`, or `all` for `-1`. A cluster source counts clusters: `all clusters`, `20,000 clusters`. |
| `len` | `min_seq_len`-`max_seq_len`. |
| `val` | `val_ratio`. |
| `clustering` | `off`, or where the clusters come from. See [Cluster subsampling](/nanoplm/guides/cluster-subsampling/#read-the-table). |

A `*` after a value means the source sets it itself instead of taking it from `data_params`.

The line under the table is one of:

| Line | Meaning |
| --- | --- |
| `Rebuild: all (first run)` | Nothing has been built in this folder yet. |
| `Up to date: all stages` | Nothing changed since the last run; DVC skips every stage. |
| `May rerun (DVC skips a stage its run cache already has): filter, split, ... Up to date: check, shuffle.` | Your edit changed the inputs of the listed stages. A stage whose new inputs DVC has seen before is restored from its cache instead of rerun. |

The `reuse` cell only says the file exists. A download that an earlier `from-yaml` run in this folder wrote is reused. A file you copied into `downloads/` yourself is not known to DVC, so the download stage deletes it and downloads again. To use a file you already have, set `fasta` to its path.

`nanoplm data from-yaml --dry-run` prints the table and the stages that would run, without running them. It needs a folder where `from-yaml` has run once (it will not create the DVC repository), and it stops at the first download that has not happened yet, because DVC cannot plan the stages that read a file that does not exist.

## Invalid sequences will stop you once

Real FASTA files contain residues outside the 20 standard amino acids. The `check` stage finds them, and with the default `drop_invalid_sequences: false` it **stops the pipeline** rather than changing your dataset without telling you:

```text title="Output (trimmed)"
Running stage 'check':
> nanoplm data check -i my_proteins.fasta -o output/data/pretrain_data/mine/validation --drop-invalid false
WARNING check: found 2 invalid sequence(s); see output/data/pretrain_data/mine/validation/invalid.fasta
Error: Validation found 2 problematic sequence(s).
  Inspect: output/data/pretrain_data/mine/validation/invalid.fasta
  Summary: output/data/pretrain_data/mine/validation/validation.json

To exclude these sequences and continue the pipeline:
    nanoplm data from-yaml --fix
```

Look at `invalid.fasta` first. A large count usually means the file is not what you thought it was. To drop them and continue:

```sh
nanoplm data from-yaml --fix
```

```text title="Output (first line)"
Set data.yaml: drop_invalid_sequences=true
```

`--fix` writes `drop_invalid_sequences: true` into your `data.yaml` (every occurrence, including one set on a source) and runs again. The `filter` stage then drops the IDs listed in `<source>/validation/invalid_ids.txt`. Because the change is in the file, `git diff` shows it.

## What you get

<FileTree>

- output/data/pretrain_data/ point pretraining.dataset_dir here
  - downloads/
    - uniprot_sprot.fasta.gz downloaded, one file per URL
  - swissprot/ this source's intermediate files
    - uniprot_sprot.fasta extracted
    - validation/
      - validation.json
      - invalid.fasta
      - invalid_ids.txt read by the filter stage
    - shuffled.fasta
    - filtered.fasta
    - split/
      - train.fasta
      - val.fasta
  - train/
    - shard_0000.bin uint8 token ids
    - shard_0000.idx.npy per-sequence lengths
    - …
  - val/
    - …
  - .data_manifest

</FileTree>

The manifest is what pretraining reads:

```yaml title="output/data/pretrain_data/.data_manifest"
# This file is AUTO-GENERATED by 'nanoplm data from-yaml'.
# DO NOT EDIT THIS FILE MANUALLY.
# To regenerate, run 'nanoplm data from-yaml' again with updated params.yaml.

pipeline_mode: pretrain
seqs_num: 20000
min_seq_len: 20
max_seq_len: 512
val_ratio: 0.1
train_dir: train
val_dir: val
train_sequences: 18000
val_sequences: 2000
num_register_tokens: 0
created_at: '2026-07-14T19:32:04.118273'
sharded: true
samples_per_shard: 2000
total_train_tokens: 6392418
```

You never edit this file. Pretraining reads `max_seq_len` and `num_register_tokens` from it, which is why `pretrain.yaml` has neither key.

## Move an old data.yaml

A `data.yaml` from before the `sources:` layout has a `data_dirs` block with `url` or `local_fasta` and seven paths. It still works. `from-yaml` reads it as one source named `main`, builds the same files in the same places, and prints the block to paste in instead:

```text title="Output"
Warning: data_dirs is the old data.yaml layout. It still works, read as one source named "main". To switch, replace data_dirs with:

output_dir: "output/data/pretrain_data"
sources:
  main:
    fasta: swissprot

and rename data_params.seqs_num to max_seqs. The new layout keeps intermediate files under output_dir/main/, so the first run after switching rebuilds them.
To skip the download, set fasta: "output/data/raw/sequences.fasta.gz" (the file already downloaded; it is read where it is, so keep it).
Then these old files can be deleted: output/data/raw/sequences.fasta, output/data/validation, output/data/raw/sequences_shuffled.fasta, output/data/filter/sequences_filtered.fasta, output/data/split.
```

So the switch is:

```yaml title="Before"
data_dirs:
  url: "https://ftp.uniprot.org/pub/databases/uniprot/knowledgebase/complete/uniprot_sprot.fasta.gz"
  local_fasta: null
  compressed_fasta:   "output/data/raw/sequences.fasta.gz"
  extracted_fasta:    "output/data/raw/sequences.fasta"
  # ... four more paths
  output_dir:         "output/data/pretrain_data"

data_params:
  seqs_num: 20000
  # ...
```

```yaml title="After"
output_dir: "output/data/pretrain_data"
sources:
  main:
    fasta: "output/data/raw/sequences.fasta.gz"   # the old download; or swissprot to download again

data_params:
  max_seqs: 20000
  # ... the rest unchanged
```

The first run after the switch rebuilds the intermediate files under `output_dir/main/` and then the shards. Keep `data_dirs` or `sources`, not both; a file with both is an error. The old name `seqs_num` still works, with a warning. A folder whose `.dvc/` was created by an old run keeps DVC's copy cache, which stores every output twice; to switch it to links, see [Stages and caching](/nanoplm/guides/cluster-subsampling/#stages-and-caching).
